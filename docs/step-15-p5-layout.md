# Step 15 · 运营台排版 v2（P5）

P4 把该有的信息都放上了页面，但仍是单列向下堆：8 个区块、近 4 屏，找“实验看板”要滚很久；发布记录和实验看板是两张表，同一条链路要来回对照；审计日志默认全量渲染，页面最底部被拉得很长。

这一步只改前端排版与交互，不动任何业务判定。

## 六处改动

| # | 改动 | 落地方式 |
|---|------|----------|
| 1 | 左侧固定目录 | `.shell` 190px + 主列；7 个锚点、当前区块高亮、待办数量徽标；≤1024px 变顶部横向 tab |
| 2 | 指标分层 | 完成率 / 否决率 / 实验判定率做成 3 张大卡（数值 + 阈值条 + 说明），代码覆盖、名额裁剪、平均调用压成一条辅助带 |
| 3 | 8/4 分栏 + 审批吸顶 | 左栏体检 / 动作 / 方案，右栏“审批与发布”`position: sticky`，切换方案不用滚回顶部；默认选中第一个方案 |
| 4 | 面板头统一 | 标题 + 数量徽标 + 一行说明；表格数字等宽、审计展开后表头吸顶 |
| 5 | 运行记录合并 | 发布记录与实验看板按 `(product_id, variant_key)` 合并，一行一个版本：状态 → 判据 → 基线/当前 → 曝光 → 结论 |
| 6 | 审计日志折叠 | 默认只显示最近 5 条，头部显示“最近 5 条 / 共 N 条”；展开后面板内滚动（`max-height: 420px`），页面高度基本不变 |

## 关键实现

**运行记录合并**
- 以 `(product_id, variant_key)` 为键取并集：实验（观察中 / 已判定）+ 发布记录。
- 排序：观察中 → 已判定 → 仅发布；同组按时间倒序。
- 只有发布记录、没有实验的版本，结论列显示“未登记实验”，不伪造状态。
- 旧指标口径不变，`experiment_board.summary` 仍用于顶部计数。

**审计折叠**
- 渲染时给第 6 行起加 `audit-more`，CSS 默认 `display:none`；展开时恢复 `table-row`。
- 展开区域 `max-height: 420px` + 内部滚动，表头 `position: sticky`。
- `#audit-toggle` 与 `#audit-more` 共用 `setAuditExpanded()`，同步 `aria-expanded`、按钮文案与底部提示；按钮元素天然支持 Enter / Space。
- 数据仍一次拉 100 条，展开不额外请求；超过 100 条时计数显示 `100+`。

**CSP 导致的旧隐患**
服务端 `Content-Security-Policy: style-src 'self'` 会丢弃所有内联 `style` 属性。旧实验进度条写的 `style="width:37%"` 实际上从未生效（一直是满格）。本次统一改为 `data-width` + 渲染后 `applyWidths()` 用 CSSOM 赋值，KPI 阈值条与曝光进度条都恢复正常。

同时删掉了 `index.html` 里唯一的内联 margin，改用 `.divider-lg`。

## 取舍与边界

- 右栏审批卡 `max-height: calc(100vh - 88px)` 内部滚动；窗口很矮时以卡片滚动换页面滚动。
- 移动端运行记录与审计表保留横向滚动，不压缩成卡片，避免同一条实验被拆成多行。
- 方案列表仍只展示前 10 个（`proposals[:10]`），运行记录展示已加载的全部（发布 + 实验并集）。
- 审计列表接口上限 100 条，折叠只影响展示，不影响导出。
